1. 概要

電子カルテの「手術予定表発行」から患者ごとの Excel を開き、 デスクトップ\症例ファイル に 001.xls、002.xls…と連番で保存します。 保存した Excel は、麻酔記録システム AIMS-ν の患者情報タブ「Excel ファイルから読み込む」で使います。

自動になる作業

もとの手作業case-export を使うと
① 電子カルテの「手術依頼箋出力」ボタンを押す手で行う（手術予定表発行ダイアログを開くところまで）
② 患者一覧で患者を右クリック →「発行プレビュー」自動
③ その患者の Excel が開く自動（電子カルテが書き込み終えるのを待つ）
④ 名前を付けて保存 → デスクトップ\症例ファイル自動（NNN.xls の連番で保存し、Excel を閉じる）
⑤ 全患者分繰り返す自動（一覧の人数を画面から読み取り、その人数分だけ処理する）

保存しない患者

麻酔の欄がちょうど「局所麻酔」の患者は保存せずに閉じ、番号を詰めます。 「局所麻酔」にほかの文字が付いているもの（例：「局所麻酔　鎮静」など）は保存します。

画面に出るのは、保存したファイル名・件数と止まった理由だけです。患者名などの患者情報は表示しません。

2. 使う前の準備

  • 使う端末：電子カルテ（手術予定表発行）と Excel が入った院内の Windows 端末。
  • プログラム：main.dist フォルダを、フォルダごと端末の好きな場所（例：デスクトップ）に置きます。中の main.exe を起動します。インストールやネット接続は要りません。
    • フォルダの中のファイルを main.exe だけ取り出して動かすことはできません。フォルダのまま使ってください。
  • 保存先：デスクトップ\症例ファイル。なければ自動で作ります（デスクトップを OneDrive に移している端末でも、Windows が示すデスクトップに作ります）。
  • 設定ファイル：main.exe と同じフォルダに settings.json ができます（患者一覧の 1 行目の位置）。フォルダに書き込めない場所に置くと、毎回測り直すことになります。

始める前に、症例ファイル の中の 001.xls などを Excel で開いていないことを確かめてください。開いていると前回のファイルを削除できず、そこで終わります。

4. 自動処理でしていること

  1. 人数を読み取る：患者一覧の 1 行目を左クリックで選び（手で選んだときと同じく青くなります）、一覧の画面の色から、行の区切り線で行の高さを、最後の患者の下にあるダークグレーの空きまでの行数で人数を求めます。画面の色はメモリ上で読むだけで、画像は保存しません。
  2. 1 人ずつ処理する：1 行目から順に、行を右クリック → メニューの「発行プレビュー」を選びます。
  3. 書き込みを待つ：開いた Excel（電子カルテの手術依頼箋のブック）に、電子カルテが値を書き込み終えるまで待ちます（データシートの内容が何回か続けて変わらなくなったら完了とみなします）。
  4. 保存する：症例ファイル\NNN.xls に保存（コピーを保存）し、ブックを保存せずに閉じます。ほかにブックがなければ Excel も終了します。
  5. 局所麻酔を除く：麻酔の欄がちょうど「局所麻酔」なら保存せずに閉じ、番号を使いません（次の患者が同じ番号になります）。
  6. 念のための確認：直前に開いた患者と同じ内容の Excel が開いたら、保存せずに閉じて止まります。

case-export が触るのは、電子カルテが開いた手術依頼箋のブックだけです。ほかに開いている Excel のブックには触りません。

5. 終わったあとの確認

  • 件数：最後に出る「保存 ○ 件、局所麻酔で除外 ○ 件」の合計が、患者一覧の人数と合っているか。
  • 順番：症例ファイル のファイルが、一覧の順（局所麻酔の患者を除く）になっているか。
  • 途中で止まったとき：止まった行より後の患者は保存されていません。7. 止まったとき・困ったときを見て、残りを手で保存するか、もう一度実行してください（もう一度実行すると、前回のファイルを削除して 1 行目からやり直します）。
  • 「※ ○○.xls と内容が同じです」が出たとき：同じ患者を 2 回開いていないか確かめてください。

6. 半自動モード

次のときは、自動で右クリックするのをやめて半自動に切り替わります。

  • 手術予定表発行ダイアログに患者一覧が見つからないとき
  • 患者一覧の画面の色から行の高さや人数を読み取れなかったとき（読み取った色の帯の一覧が表示されます）
見張っています。電子カルテで患者を右クリック →「発行プレビュー」してください。 終わったら Ctrl+C で終了します。

半自動では、右クリック →「発行プレビュー」を手で行います。Excel が開くと、case-export が書き込み完了を待って保存し、Excel を閉じます（局所麻酔の除外も同じように行います）。

  1. 1 人目を右クリック →「発行プレビュー」。
  2. 「001.xls を保存しました」と出て Excel が閉じたら、次の患者を同じように開きます。
  3. 全員分終わったら、黒い画面で Ctrl+C を押して終了します。件数が表示されます。

7. 止まったとき・困ったとき

止まったときは、黒い画面に理由が出ます。「○ 行目」は患者一覧の上から数えた行です。その行より前の患者は保存済みです。

自動処理が止まったとき

表示原因対処
マウスが大きく動いたので止めました。 処理中にマウスを行 3 つ分より遠くへ動かした。 もう一度実行してやり直します（前回のファイルは削除されます）。処理中はマウスに触らないでください。
※ ○ 行目が別の画面に隠れているので止めました。 患者一覧の上に別の画面（黒い画面・通知など）が重なっている。 重なっている画面をずらしてから、もう一度実行します。
※ ○ 行目で「発行プレビュー」のメニューが出なかったので止めました。 右クリックしても「発行プレビュー」のメニューが出なかった。行の位置がずれている、電子カルテが応答していない、など。 電子カルテの画面を確かめてから、もう一度実行します。何度も出るときは settings.json を削除して測り直します。
※ ○ 行目で、60 秒たっても Excel を保存できなかったので止めました。 Excel が開かない、または開いたが書き込みが終わらない・保存できない。 開いている Excel があれば手で閉じ、もう一度実行します（または残りを手で保存します）。
※ ○ 行目で直前と同じ患者が開いたので、保存せずに閉じて止めました。 人数を多く読み取り、一覧の下の空いた行を右クリックした（最後の患者がもう一度開く）。または、一覧に同じ患者が続けて 2 回並んでいる。 件数の合計が一覧の人数と合っていれば、全員分保存できています。同じ患者が 2 回並んでいるときは、2 回目以降を手で保存します。
※ ○ 行目で止めました。 その患者の保存に失敗した（理由は直前に表示）。 直前の表示を見て、その患者以降を手で保存するか、もう一度実行します。
患者一覧の下端まで処理しました。 一覧の見えている範囲の一番下まで処理した。 件数の合計が一覧の人数と合っているか確かめます。足りなければ、残りを手で保存します。

そのほか

  • 違う行を右クリックするようになった：main.exe と同じフォルダの settings.json を削除し、次の起動で 1 行目の位置を測り直します。

8. 開発・持ち込み

ファイル構成

ファイル中身
main.py本体（自動処理と半自動）。exe にすると main.exe。
inspect_ui.py実機の画面の作りを調べるツール（読み取りのみ）。exe にすると inspect_ui.exe。
build.batWindows 用のビルドスクリプト。
tests/Windows なしで確かめられる部分のテスト。
pyproject.tomluv のプロジェクト定義（依存は pywin32・pywinauto）。
changelog.md変更履歴。

ビルド（ネットにつながった Windows PC）

院内端末には exe（standalone のフォルダ）しか持ち込めないので、ビルドは別の Windows PC で行います。

  1. uv を入れておきます（Python 3.10 は uv が用意します）。
  2. リポジトリを pull して最新にします。
  3. build.bat を実行します。 
    build.bat              （ダブルクリックでも可。main をビルド）
build.bat inspect_ui   （調査ツールをビルド）
  4. 終わると dist\main.dist\main.exe（または dist\inspect_ui.dist\inspect_ui.exe）ができます。
  • 初回のビルドは 10 分以上かかることがあります。
  • build.bat はビルド用の .venv-build を作り、Nuitka・pywinauto・pywin32・comtypes を決まった版で入れます。.venv や pyproject.toml は変えません。
  • onefile（exe 1 個）にはしません。ウイルス対策ソフトに引っかかるためです。

持ち込み

  • dist\main.dist フォルダをフォルダごと院内端末にコピーします。中の main.exe を起動します。
  • 新しい版に入れ替えるとき、前の版のフォルダにある settings.json を新しいフォルダに移すと、1 行目の測り直しを省けます（拡大率が同じ場合）。

settings.json

患者一覧の 1 行目の位置を記録したファイルです。患者情報は含みません。

{
  "version": 2,
  "dpi": 96,
  "x": 120,
  "y": 30
}
  • dpi：測ったときの表示の拡大率（96 = 100%）。違っていれば測り直します。
  • x・y：患者一覧の左上から見た 1 行目の位置（画面の点）。
  • 削除すると次の起動で測り直します。

画面調査ツール inspect_ui.exe

電子カルテや Excel の画面の作り（部品の種類や名前）を調べ、患者情報を伏せたレポートに書き出します。クリックやキー入力は一切しません。電子カルテの更新で動かなくなったときの調査に使います。

  1. inspect_ui.exe を起動すると 10 秒数えます。その間に調べたい画面を前面に出します（クリックして前に出す）。
  2. 次の場面で 1 回ずつ実行します。
    1. 「手術依頼箋出力」ボタンが見えている電子カルテの画面
    2. 手術予定表発行ダイアログ
    3. 患者を右クリックしてメニューを開いたところ
    4. 発行プレビューで Excel が開いたところ
    5. その Excel を手で閉じたあと
  3. 今のフォルダに inspect_report_<日時>.txt ができます。

コマンドプロンプトからは次のオプションが使えます。

inspect_ui.exe --delay 20      待ち時間を 20 秒にする
inspect_ui.exe --allow 発行    伏せ字にしない文字列を足す（複数可）
inspect_ui.exe --out D:\work   レポートを書き出すフォルダ

ボタン・メニュー・列見出し以外の文字（タイトル・一覧の行・入力欄など）は文字数だけにして伏せますが、レポートを共有する前に、患者名などが含まれていないか必ず中身を確かめてください。

テスト（開発環境）

電子カルテや Excel を使わない部分（ファイル名の連番、局所麻酔の判定、一覧の色の読み取り、設定ファイルなど）は、Windows がなくてもテストできます。uv run は使わず、インタプリタを直接呼びます。

.venv/bin/python -m unittest discover -s tests

電子カルテ・Excel の画面操作にかかわる部分は、院内端末でしか確かめられません。

技術的な仕組み（参考）

  • 電子カルテの患者一覧（AfxOleControl42）は中の行を部品として取れないので、座標で右クリックします。右クリックで出たメニューは UI Automation で「発行プレビュー」を選びます。
  • Excel は COM で、電子カルテが開いたブック（C:\SSI\Excel\手術\手術依頼箋.xls）を見つけ、SaveCopyAs で保存します。麻酔の欄はデータシートの B14・C14 を見ます。
  • COM はメインの処理で STA（sys.coinit_flags = 2）として最初に初期化し、別スレッドでは使いません。
  • nuitka の exe では、pywinauto を読み込む前に sys.frozen = True にしています（comtypes の ImportError: Typelib different than module を避けるため）。

9. 注意事項

  • 自動処理の間は、マウスとキーボードに触らないでください。
  • 処理が終わったら、黒い画面をクリックしてから Enter で閉じてください。
  • 保存した件数と除外した件数の合計が一覧の人数と合っているか、ファイルが一覧の順になっているかを必ず確かめてください。
  • 同じ患者が一覧の中で続けて 2 回並んでいると、2 回目で止まります。
  • 実際の患者の Excel ファイルや、電子カルテの画面キャプチャをリポジトリや院外に持ち出さないでください。
  • 問い合わせやレポートの共有では、患者名などの患者情報を含めないでください。
